# School Bud-E Mobile App Updates

## Changes Made

### 1. Shop Key Persistence Fixed ✅

**Problem**: The shop key (API key) was not being persisted properly, causing frustration for users who had to re-enter it frequently.

**Solution**: 
- Added auto-save functionality to the AppContext that saves settings automatically when they change
- Added auto-save timer in SettingsScreen that saves changes 2 seconds after user stops typing
- Enhanced the `setLanguage` function to automatically save settings when language changes

**Files Modified**:
- `src/context/AppContext.tsx` - Added auto-save on language change
- `src/screens/SettingsScreen.tsx` - Added auto-save timer and improved persistence

### 2. Password Manager Integration ✅

**Problem**: When entering server URL and shop API key, the app didn't offer to save credentials to password manager.

**Solution**:
- Added `textContentType="URL"` and `autoComplete="url"` to server URL input
- Added `textContentType="password"` and `autoComplete="password"` to API key input
- These attributes enable iOS/Android password managers to offer to save and autofill credentials

**Files Modified**:
- `src/screens/SettingsScreen.tsx` - Enhanced TextInput components with password manager support

### 3. Replaced Games with Graphs ✅

**Problem**: User wanted graph features instead of game features to view AI-generated graphs.

**Solution**:
- Created new `GraphsScreen.tsx` to replace `GamesScreen.tsx`
- Implemented graph visualization using WebView with Cytoscape.js
- Added graph storage and management functionality
- Updated navigation to use "Graphs" tab instead of "Games"
- Created `graphService.ts` for managing graph data persistence

**Files Created**:
- `src/screens/GraphsScreen.tsx` - New screen for viewing and managing graphs
- `src/services/graphService.ts` - Service for graph data management

**Files Modified**:
- `App.tsx` - Updated navigation to use GraphsScreen instead of GamesScreen
- `package.json` - Added react-native-webview dependency
- `src/screens/ChatScreen.tsx` - Added graph detection and saving from AI responses

### 4. Graph Features

**Features Implemented**:
- **Graph Storage**: Graphs are automatically saved when AI generates them in chat
- **Graph Visualization**: Interactive graph viewing using Cytoscape.js in WebView
- **Graph Management**: List, view, and delete saved graphs
- **Demo Graph**: Option to create a demo graph for testing
- **Responsive Design**: Graphs adapt to mobile screen sizes
- **Multilingual Support**: German and English language support

**Graph Data Structure**:
```typescript
interface GraphNode {
  item: string;
  childItems?: string[];
  connections?: { from: string; to: string }[];
  position?: { x: number; y: number };
}

interface StoredGraph {
  id: string;
  name: string;
  items: GraphNode[];
  createdAt: string;
  updatedAt: string;
}
```

## Installation Requirements

To use these updates, you'll need to install the new dependency:

```bash
npm install react-native-webview@^13.12.3
```

For iOS, you may also need to run:
```bash
cd ios && pod install
```

## Usage

### Viewing Graphs
1. Navigate to the "Graphs" tab (formerly "Games")
2. Any graphs generated by Bud-E in chat will appear here automatically
3. Tap on a graph to view it in full-screen interactive mode
4. Use the demo graph option to test the functionality

### Settings Persistence
1. Enter your server URL and shop API key in Settings
2. The app will automatically save changes after 2 seconds of inactivity
3. Your password manager should offer to save these credentials
4. Settings persist across app restarts

### AI Graph Generation
1. In chat, ask Bud-E to create knowledge graphs or diagrams
2. When Bud-E generates graph data, it's automatically saved
3. View saved graphs in the Graphs tab

## Technical Notes

- Graph visualization uses Cytoscape.js for interactive network diagrams
- Data is stored locally using AsyncStorage
- WebView enables rich graph interactions on mobile
- Auto-save prevents data loss and improves user experience
- Password manager integration follows iOS/Android best practices
